# UI API design audit

> Review the public API by concept, starting with the changes most likely to reduce agent mistakes.

Status: recommendations pending review, except the explicitly [approved decisions](approved-decisions.md). These are future designs, not supported API instructions. Reviewed source at `85e06e06` on 2026-10-13. No runtime targets were run. Agent usability is a design judgment, not a measured benchmark.

The tree follows the current import boundaries: `root/` for `@octane-xplat/ui`, then `ios/`, `android/`, `native/`, `web/`, and `theme/`. Folders below `root/` group concepts; they are not current import subpaths. Closely related components share a page. Each recommendation has a short reason and an illustrative TypeScript shape.

## Start with these five changes

The [entrypoint boundary](approved-decisions.md) is approved. These five recommendations remain pending review, in priority order:

1. [Honest platform contracts](root/contracts/platform-support.md) and [consistent export surfaces](root/contracts/conditional-surface.md). Accepted props must have supported behavior, and the same import must expose the same intended API across targets.
2. [One state and event convention](root/contracts/state-events.md). Eliminate duplicate flags and make callback payloads predictable.
3. [Exact selection and menu modes](root/forms/select.md), [menus](root/overlays/menus.md). Use unions that reject contradictory values.
4. [Useful public types](root/contracts/props.md). Replace broad `any`, share collection contracts, and type handles.
5. [One vocabulary for names and types](root/contracts/names.md). Use specific frontend concepts and one `ComponentProps` spelling; remove ambiguous aliases and orphan types.

## Scope and evidence

The export index covers the union of 341 root value exports and all 661 named root types across export conditions, plus the platform entrypoints and published CSS paths. The shared web/mobile/default surface has 339 values and 628 named types; the larger counts include conditional additions. Types are reviewed with their owning concepts; this is not a field-by-field verification of every alias. This review stays outside the published guide tree so proposals remain separate from supported app-building instructions. Raw `src` files shipped in the tarball are not treated as supported deep imports outside the export map. Other packages are outside scope.

[Value export index](exports.md) and [type export index](types.md) provide complete lookup without lengthening the recommendation pages. Source links are evidence for current facts. Every TypeScript block describes a proposed partial contract, not a full component implementation or a copyable import from the current package.

No public behavior, setup, or supported workflow is changed by this audit, so no recipe needs reconciliation. Implementation would require a deliberate breaking release and corresponding migration, documentation, example, and recipe updates. Start with canonical contracts before mechanically renaming every export.

Validation: all public value exports have a concept owner; all named public types have an index entry. Local links and source-line anchors resolve, Markdown parses with the repository parser, and the proposed TypeScript shapes pass a standalone strict typecheck. These checks do not establish runtime behavior or compatibility of the proposed API.

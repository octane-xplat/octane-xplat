# Recommended public API changes

A compact change list, ordered by impact on correct agent use. The [whole-package vision](package-vision.md) supplies target contracts for all 126 concepts, including those governed by the cross-cutting changes here. These are target contracts, not implementation instructions or currently supported APIs. D1–D6 in [approved decisions](approved-decisions.md) establish the direction; the concrete recommendations below use the reviewer’s authorized judgment. Exact names follow **Astryx → React Aria → React Native → generic frontend**, with equivalent semantics. Retain reference-backed names rather than automatically replacing them with generic names.

## First: remove misleading contracts

| API or boundary                                                                                                                                                                     | Recommended change                                                                                                                                                       | Why                                                                                   |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| [Root and conditioned exports](root/contracts/conditional-surface.md), [CSS exports](theme/stylesheets.md)                                                                          | Give the shared import the same intended values and types on every target; make development and published paths agree. Move target-specific contracts to explicit paths. | An import that works locally must remain valid after publishing and changing targets. |
| [FocusScope](root/accessibility/focus-scope.md), [focus hooks](root/accessibility/focus-hooks.md), [useGridList](root/collections/grid-list.md), [Outline](root/content/outline.md) | Implement accepted behavior or expose an explicit supported subset/capability. Separate DOM discovery from portable outline data.                                        | Successful typechecking currently conceals unsupported or different behavior.         |
| [iOS controls](ios/controls.md), [Android controls](android/controls.md)                                                                                                            | Honor the field-state and accessibility props they accept, or narrow their public types.                                                                                 | Disabled and labeled controls must mean what their types promise.                     |
| [Button](root/actions/button.md), [Progress / Meter](root/content/progress.md)                                                                                                      | Expose action failures; give Meter the semantics and accessibility role of a meter.                                                                                      | Hidden failures and incorrect roles cause incorrect behavior despite plausible code.  |
| [Prop clearing](next-recommendations.md#r4-make-declarative-updates-and-prop-removal-predictable)                                                                                   | Removing an optional shared prop restores its documented default. Specify omitted, undefined, null, and explicit reset semantics per contract.                           | Editing JSX should describe the current UI without retained host values.              |

## Next: reduce choices and strengthen feedback

| API or boundary                                                                                                                                                               | Recommended change                                                                                                                                                      | Why                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| [Imports](root/contracts/imports.md)                                                                                                                                          | Keep general UI at the root; give routing, data, Markdown, and chat their canonical `/routing`, `/data`, `/markdown`, `/chat` entrypoints with related types and hooks. | Purpose boundaries make imports inferable without scattering ordinary UI.           |
| [Names](root/contracts/names.md), [public props](root/contracts/props.md)                                                                                                     | Apply the naming hierarchy to each comparable contract; export matching props, events, item types, and handles. Remove public internal fields and unbounded `any`.      | Discoverable, precise declarations support completion and repair.                   |
| [Button](root/actions/button.md), [state/events](root/contracts/state-events.md), [menus](root/overlays/menus.md)                                                             | Choose one spelling and behavior per state/action; remove overlapping disabled/loading/open aliases and competing action callbacks.                                     | Aliases and competing handlers leave precedence ambiguous.                          |
| [TextInput](root/forms/text-input.md), [boolean inputs](root/forms/boolean-inputs.md), [choices](root/forms/choice-lists.md), [overlays](root/overlays/dialog.md)             | Provide consistent controlled, initial, and change roles where supported; define controlled-plus-initial conflicts and callback payloads.                               | State ownership should transfer predictably between related components.             |
| [Selector](root/forms/select.md), [menus](root/overlays/menus.md), [disclosure](root/actions/disclosure.md)                                                                   | Tie selection mode to its exact value and event type; distinguish action items, links, sections, and separators.                                                        | Invalid combinations should fail while code is being written.                       |
| [Date inputs](root/forms/date-inputs.md), [Calendar](root/forms/calendar.md), [NumberInput](root/forms/number-input.md)                                                       | Establish empty/clear values per family; distinguish local dates, local date-times, and instants; replace contradictory picker flags with one strategy.                 | Empty and temporal values should not change meaning between consumers.              |
| [Time](root/content/time.md), [Stack](root/layout/stack.md), [resizing](root/layout/resizing.md), [query cache](root/state/query-cache.md)                                    | Use explicit consistent units for timestamps, durations, layout, and tokens; remove magnitude-based timestamp guessing.                                                 | A number should have one meaning independent of the receiving API.                  |
| [Table](root/collections/table.md), [VirtualList](root/collections/virtual-list.md), [TreeList](root/collections/tree.md), [collection data](root/state/collection-data.md)   | Preserve item generics; share stable key and selection contracts; distinguish keys from indices; expose controlled expansion where needed.                              | Data can move between stores and views without losing identity or type information. |
| [Routes](root/navigation/routes.md), [route definitions](root/navigation/route-definitions.md), [PowerSearch](root/forms/power-search.md), [Table](root/collections/table.md) | Infer route parameters, filter values/operators, and column keys from their defining schema through all consuming methods.                                              | Invented names and incompatible values become actionable type errors.               |

## Then: make composition and operations reliable

| API or boundary                                                                                                                                                           | Recommended change                                                                                                                                                                    | Why                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| [ComplexSelector](root/forms/complex-selector.md), [Item / List](root/collections/item-list.md), [Table](root/collections/table.md)                                       | Use named context fields for multi-argument render callbacks and consistent slot roles within related families.                                                                       | Agents can inspect available fields instead of memorizing positional conventions.                    |
| [Field](root/forms/field.md), [Tabs](root/navigation/tabs.md), [menus](root/overlays/menus.md), [focus](root/accessibility/focus-scope.md)                                | Make required providers/anatomy explicit; make label, description, error, keyboard, and focus relationships part of normal composition.                                               | Correct accessibility should follow the preferred structure with fewer manual connections.           |
| [Bottom sheets](root/overlays/bottom-sheet.md), [toasts](root/overlays/toast.md), [windows](root/navigation/windows.md), platform modals                                  | Return typed handles for the created instance, including relevant completion, close, and disposal operations; agree on shared window results and data behavior.                       | Concurrent resources need explicit ownership and observable outcomes.                                |
| [ScrollableArea](root/layout/scrollable-area.md), [VirtualList](root/collections/virtual-list.md), [WebView](root/media/webview.md), [refs](root/utilities/refs-props.md) | Export typed portable handles; bound raw host access; make ref composition preserve each consumer’s ref.                                                                              | Consumers should not guess host methods or lose an existing ref while composing props.               |
| [Stores](root/state/store.md), [collection data](root/state/collection-data.md), [indicators](root/styling/indicators.md)                                                 | Distinguish reactive reads from snapshots; expose readonly snapshots, separate value assignment from updater functions, and define selector equality.                                 | Mutations and subscriptions become visible rather than relying on hidden reactivity rules.           |
| [Async lists](root/state/async-list.md), [query cache](root/state/query-cache.md), [Button](root/actions/button.md)                                                       | Expose completion, pending/error state, cancellation where supported, and pagination readiness; specify overlapping requests and retries.                                             | Agents can await, recover, and avoid repeating operations blindly.                                   |
| [WebView](root/media/webview.md), [Markdown](root/content/markdown.md), [AppShell](root/navigation/app-shell.md), [chat tool calls](root/chat/tool-calls.md)              | Make alternative content sources and state-dependent configurations exclusive and precisely typed.                                                                                    | Permissive bags and independent optional fields hide incompatible choices.                           |
| [Theme](root/styling/theme.md), [styled](root/styling/styled.md), [icons](root/styling/icons.md)                                                                          | Distinguish preference from resolved appearance; type variants and icon identifiers; bound platform customization explicitly.                                                         | Styling decisions should be discoverable through the same public contract as components.             |
| [Diagnostics](next-recommendations.md#r5-make-runtime-diagnostics-usable-as-repair-instructions), [route definitions](root/navigation/route-definitions.md)               | Give runtime contract failures stable codes, field paths, expected shapes, and repair hints. Reject duplicate route names; report missing prerequisites.                              | Runtime feedback should identify the smallest correct edit.                                          |
| [Chat composer](root/chat/composer.md), [tokens](root/chat/tokens.md), [messages](root/chat/messages.md), [scrolling](root/chat/layout-scroll.md)                         | Make drafts serializable and tokens round-trip; separate send/cancel from draft state and sender/delivery from presentation; expose following-latest behavior.                        | Agents can preserve drafts and update messages without coordinating undocumented parallel state.     |
| [Markdown streaming](root/content/markdown-streaming.md), [syntax](root/content/syntax.md), [Outline](root/content/outline.md)                                            | Offer one streaming parser, readable document data, and typed code tokens/offsets at the Markdown entrypoint; keep tuning and segmentation plumbing private.                          | Consumers can render streamed content without assembling internal helper sequences.                  |
| [Search sources](root/forms/typeahead.md), [CommandPalette](root/navigation/command-palette.md), [chat triggers](root/chat/tokens.md)                                     | Share request-scoped abortable search and distinguish query text, selected data, and executed commands.                                                                               | Sharing a source should not let one consumer cancel another consumer’s request.                      |
| [SafeArea](root/layout/screen-insets.md), [keyboard avoidance](root/layout/keyboard-insets.md), [measurement](root/layout/measure.md), [Grid](root/layout/grid.md)        | Specify inset consumption, measurement coordinate space/readiness, and a bounded grid grammar with explicit numbering.                                                                | Layout values should mean the same thing without inspecting the active host.                         |
| [Keyboard](root/utilities/keyboard.md), [gestures/animation](root/styling/animation-gestures.md), [clipboard](root/utilities/clipboard.md)                                | Publish normalized event domains, explicit units and attachments, and observable animation/copy outcomes.                                                                             | Interaction and sequencing need precise contracts beyond a generic event or host object.             |
| [iOS](ios/navigation.md), [Android](android/navigation.md), [NativeScript hosts](native/hosts.md), [web](web/compatibility.md)                                            | Give authentic widgets matching public types and shared value/identity contracts; separate host integration and DOM-specific APIs from portable UI.                                   | Platform choices stay explicit without competing aliases for unrelated contracts.                    |
| [Router](root/navigation/routes.md), [query cache](root/state/query-cache.md), [icon registry](root/styling/icons.md), [group defaults](root/actions/button-group.md)     | Make app/instance scope and child-over-parent precedence explicit; keep ordinary components usable without unrelated providers.                                                       | Local component changes should not depend on hidden global initialization or alter another consumer. |
| Public declarations and examples                                                                                                                                          | Put imports, defaults, units, errors, prerequisites, and related APIs beside their declarations; show one preferred supported composition. Keep migration aliases clearly deprecated. | Agents need a reliable local answer rather than scattered conventions.                               |

The linked concept pages supply detailed reasoning and source evidence. The priorities are design judgments; no agent benchmark or runtime qualification of the proposed API has been performed. Breaking changes need migration guidance and reconciliation of supported docs, examples, and recipes when implemented.

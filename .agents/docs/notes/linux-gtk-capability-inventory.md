# Linux GTK capability inventory and resolution mapping

> The master list every GTK coverage item (7a–7d) implements against. Every
> capability currently offered to Linux applications is listed with its native/
> hosted/service resolution and a verification field filled during
> implementation.

Plan item **2** of `octane-linux-gtk-backend` (frozen plan
`6b11d11f-f501-4e99-8f72-dd6f01fe976b`), recorded 2026-10-11 at repository
revision `85a66900`. Research evidence only — this record authorizes no
implementation and claims no runtime, accessibility, or presentation
qualification. It was produced by surveying the repository surface, not from the
plan text alone; source anchors are cited inline.

## How to read the tables

| Column                | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Capability            | The public surface — export, service, config key, or workflow — exactly as consumers see it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| GTK mapping           | `native` = GTK widget(s) owned by the universal renderer; `self-drawn` = rendered by Octane on a GTK container with explicit a11y (the shared presentation contract is retained — plan: "shared self-drawn controls retain their presentation contract"); `hosted` = explicit hosted WebKit surface inside the GTK tree, permitted only for required web/media content; `service` = platform/host service with no widget; `infra` = runtime, toolchain, or contract with no widget. | Resolution / fallback | What the capability resolves to under each renderer request, and the expected failure behavior. | Owner                 | Suggested implementation-owner grouping by plan work item: **S5** = initial slice/adapter foundation, **6b** = renderer selection/packaging/diagnostics, **7a** = components/composition, **7b** = input/editing/accessibility, **7c** = window/app/platform services/theme/leaves, **7d** = hosted surfaces.                                                                                                                                                                                                                                                     |
| Verification          | Separate status field filled during implementation (`pending` for every row here — this inventory assigns, it does not verify).                                                                                                                                                                                                                                                                                                                                                                                                                                   |

## Resolution model — grounded in the repo

Facts the mapping is built on:

- **Linux today is DOM-in-WebKitGTK.** `apps/linux/vite.linux.config.ts` resolves
  `conditions: ['linux', 'web']` and the suffix chain `.linux.*` → `.web.*` →
  unsuffixed. The GJS host (`packages/cli/src/linux/host/gjs-host.js`) mounts an
  `Adw.ApplicationWindow` + `WebKitWebView`; app code runs inside WebKit, not in
  GJS. The boundary guard allows `{linux, web}` tags in a linux bundle
  (`packages/cli/src/vite.ts` `boundaryAllowed`).
- **The macOS AppKit renderer is the universal-driver precedent.**
  `packages/macos-renderer` implements `UniversalHostDriver`
  (`octane/universal/native`: `prepareBatch`, `getPublicInstance`,
  capability tables) and keeps per-target exports in
  `packages/ui/src/index.macos.ts`. `.macos.tsrx` variants reuse the shared
  native intrinsic vocabulary with `@jsxImportSource
@octane-xplat/macos-renderer`. The GTK backend follows this pattern: a new
  renderer package plus GTK-conditioned component variants and its own barrel.
- **The shared intrinsic vocabulary is fixed.** `packages/jsx/src/shared.d.ts`
  `NativeElements` declares 39 NativeScript-baseline tags, `#text`, and 9
  extension tags (`cachedimage`, `svgview`, `xplatvideo`, `nscanvas`,
  `xplatlottie`, `pager`, `animatedimage`, `applesigninbutton`,
  `googlesigninbutton`); leaves augment the interface. The macOS driver
  implements a practical subset: `stack`, `flexboxlayout`, `gridlayout`,
  `absolutelayout`, `label`, `#text`, `span`, `button`, `scrollview`,
  `textfield`, `textview`, `switch`, `slider`, `image`, `webview` —
  `packages/macos-renderer/src/index.ts` (~1993–2050). GTK must cover at least
  the intrinsics the shared GTK variants actually emit.
- **Two different meanings of "linux" must not collide.** Existing `.linux`
  files assume the webview context: `files.linux.ts`,
  `notifications.linux.ts`, `secure-storage.linux.ts` re-export `.web` leaves
  that call `__xplatBridge`; `index.linux.ts` re-exports the web barrel plus
  `windows.linux` and `colorScheme.linux`. Those leaves are meaningless in a
  GJS app process (no DOM, no webview transport). The plan requires a distinct
  universal-compatible resolution mode; this inventory therefore treats
  **`.linux`/`linux` condition = the WebKit renderer** and assumes a **new
  condition/suffix for the GTK renderer** (name is the implementer's choice;
  `linuxgtk` and `gtk` are candidates). Under a "prefer GTK, fall back"
  package both variants ship; only one executes per mount.
- **Service substrate changes.** On the webview renderer, host services travel
  `webkit.messageHandlers.xplat` → `gjs-host.js` (wire contract in
  `packages/platform/src/bridge.linux.ts`; service table in
  `packages/platform/src/host-services.ts`). In a GJS app process there is no
  webview transport; services need an in-process host surface — the direct
  precedent is `packages/platform/src/index.macos.ts` reading a
  `__xplatAppKit` global installed by the host. Every `.web` service leaf that
  today rides DOM APIs (navigator, document, localStorage, crypto, Workers)
  needs a GJS answer: host surface, direct GI call, or explicit unsupported.
- **Component count.** `packages/ui/src/index.shared.ts` exports ~319 names
  (components, hooks, service functions, and type aliases); `props.ts` defines
  ~596 exported prop/contract interfaces — the shared prop contract is one
  family, preserved verbatim.

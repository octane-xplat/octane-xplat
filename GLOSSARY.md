# Glossary

Terms bespoke to Octane Xplat, or whose meaning here differs from what an
agent would normally assume. Each entry explains the local distinction and
links to its documentation. Standard programming vocabulary is outside this
glossary's scope.

| Term                     | Meaning in Octane Xplat                                                                                                                                                                                         | Documentation                                                                                                                                                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chrome-reset`           | A component category in which Xplat replaces an OS control's visible decoration so its appearance matches across supported targets, while retaining native behavior such as text editing.                       | [Normalization classes](docs/start/architecture.md#normalization-classes)                                                                                                                                        |
| Development action       | A named, app-declared function exposed to development tooling with declared inputs, result, and side effects. A component-owned action invokes its most recently attached handler.                              | [Development actions](docs/testing/development-actions.md)                                                                                                                                                       |
| Development effect       | A development-tool command that broadcasts to every attached handler and reports how many ran. It runs when invoked through the action registry.                                                                | [Component actions and effects](docs/testing/development-actions.md#attach-actions-from-components)                                                                                                              |
| Element vocabulary       | The built-in JSX tags a file uses, such as DOM elements or native views. Each implementation file uses one vocabulary, even when the app supports several renderers.                                            | [Platform file rules](.agents/skills/octane-xplat/references/platform-leaves.md#rules)                                                                                                                           |
| `event-handler-dispatch` | The probe runner's evidence label for invoking a view's event handler directly. It establishes handler behavior, without establishing OS input delivery, hit-testing, or keyboard and accessibility navigation. | [Probe evidence](.agents/docs/probing.md#write-a-case)                                                                                                                                                           |
| Hook slot                | A compiler-assigned location for a hook's state, tied to its source call site. Each call site has its own identity, including calls inside conditions.                                                          | [Octane hook identity](.agents/skills/octane-xplat/references/octane.md#hooks-belong-to-call-sites-not-call-order)                                                                                               |
| `hosted`                 | A component category in which matching across platforms covers the outer frame and Xplat-drawn controls. An OS or engine draws the interior content, such as the page inside a `WebView`.                       | [Normalization classes](docs/start/architecture.md#normalization-classes)                                                                                                                                        |
| JSX facade               | The type-only `@octane-xplat/jsx` package that supplies native JSX tags and host-handle types; its `/dom` entry supplies DOM types. Selecting it changes type checking, not the runtime renderer.               | [JSX and host types](docs/platform/module-resolution.md#typescript)                                                                                                                                              |
| Leaf package             | A separate feature package that owns an external dependency or system lifecycle, such as a native plugin, JS engine, or platform host integration. A specialized UI API alone does not warrant a leaf package.  | [Package boundaries](AGENTS.md#critical-rules)                                                                                                                                                                   |
| Normalization class      | A component category that defines which appearance and behavior Xplat promises to match across supported targets, and which parts belong to an OS or engine.                                                    | [Normalization classes](docs/start/architecture.md#normalization-classes)                                                                                                                                        |
| Ownerless service        | A global imperative UI service that renders content in a separate Octane root. Its content does not inherit context providers from the code that called it.                                                     | [Temporary surface ownership](docs/app/primitives.md#own-temporary-surfaces)                                                                                                                                     |
| `platform-authentic`     | A component category that preserves the platform's own control appearance and behavior. These widgets use explicit platform package entrypoints; matching other platforms is outside their contract.            | [Normalization classes](docs/start/architecture.md#normalization-classes)                                                                                                                                        |
| Platform leaf            | A platform implementation file selected behind a common import, such as `Card.web.tsrx`. It implements the same public module contract as its siblings, with platform-specific internals.                       | [Choosing a variant](docs/platform/module-resolution.md#choosing-a-variant)                                                                                                                                      |
| Recipe                   | An internal specification of what documentation must enable an app developer to accomplish, with explicit acceptance criteria. The tutorial and runtime verification are maintained separately.                 | [Documentation recipes](.agents/docs/recipes/README.md)                                                                                                                                                          |
| `self-drawn`             | A component category in which Xplat owns the whole appearance and behavior. Both must match across supported targets, including every pixel of the control.                                                     | [Normalization classes](docs/start/architecture.md#normalization-classes)                                                                                                                                        |
| Source owner             | The mounted part of the Octane tree that supplies presented content's context and controls its lifetime. For scoped services, this is determined by where their returned element is rendered.                   | [Source ownership](.agents/docs/notes/portal-boundaries.md#source-ownership)                                                                                                                                     |
| Template branch          | An `@if`/`@else` or `@switch` arm with its own render scope. Switching arms remounts their contents, even when both render the same component.                                                                  | [Template branch identity](.agents/skills/octane-xplat/references/octane.md#template-branches-remount-their-contents)                                                                                            |
| Template children        | Content written between component tags in an Octane template. It reaches the component as a compiled render body, so shared components cannot enumerate it as an array of elements.                             | [Opaque children](.agents/skills/octane-xplat/references/octane.md#children-are-opaque)                                                                                                                          |
| TSRX                     | TypeScript and JSX with opt-in syntax for templates that produce JSX, including `@{ ... }`, `@if`, and `@for`. Its source files use the `.tsrx` extension.                                                      | [TSRX syntax](.agents/skills/tsrx/SKILL.md)                                                                                                                                                                      |
| Universal runtime        | The Octane runtime that drives native hosts through renderer adapters. It requires compiler-defined components and supports a specific subset of Octane's runtime imports.                                      | [Native runtime subset](.agents/skills/octane-xplat/references/octane.md#the-native-runtime-subset); [compiled roots](.agents/skills/octane-xplat/references/octane.md#universal-roots-take-compiled-components) |
| Unsuffixed file          | In a set of platform variants, the file without a platform suffix, such as `Card.tsrx`, is the native default. A `.web` sibling supplies the browser or DOM webview implementation.                             | [File variants](docs/platform/module-resolution.md#file-variants)                                                                                                                                                |

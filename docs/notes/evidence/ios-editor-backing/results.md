## NativeScript metadata check: RUN, known loss bug REPRODUCES (2026-10-06)

[metadata-check.sh](metadata-check.sh) reproduces the NativeScript iOS metadata build step verbatim for the arm64 simulator slice: it invokes `objc-metadata-generator` from `@nativescript/ios` 9.1.0 (`framework/internal/metadata-generator-arm64/bin/`, bundled clang 17) with `-fmodules`, `-output-bin/-output-umbrella/-output-typescript/-output-yaml`, and framework search paths covering the SDK plus a wrapper framework exposing `SurfaceProbe-Swift.h` as module `XplatEditorSurface`.

```bash
goddard-agent resource run '{"resources":{"native_builds":1},"purpose":"iOS editor bridge compile/link + metadata diagnostic"}' -- \
  bash docs/notes/evidence/ios-editor-backing/metadata-check.sh \
    "$GENBIN" "$probe_output" "$meta_output"
```

Observed result, summarized by the generator itself:

```text
Result: 43 declarations from 8 top level modules
253 errors generated.
```

Exit status 0 and `metadata-arm64.bin` written — the silent-loss pattern: success exit while most declarations drop.

### Exactly which declarations drop

Serialized (the only survivors): `AlarmKit`, `AppTrackingTransparency`, `FocusEngine`, `IOSurface`, `MetalPerformanceShaders`, `SystemConfiguration`, `SystemExtensions`, and the probe's own `XplatEditorSurface` — 43 declarations total.

Dropped entirely (zero declarations serialized): **Foundation, ObjectiveC, UIKit, WebKit, CoreFoundation, CoreGraphics, QuartzCore, CoreText, Security, Darwin/dispatch and every module depending on `_DarwinFoundation1`** — i.e. `NSObject`, `NSString`, `NSArray`, `NSDictionary`, `NSAttributedString`, `NSRange`, `UIView`, `UITextView`, `UITextInput`/`UITextRange`, `NSTextStorage`, `NSLayoutManager`, `NSTextContainer`, `UIViewController`, `WKWebView`, `WKNavigationDelegate`, `WKUIDelegate`, and the rest of the surface the adapter needs.

Partial loss on the adapter class itself: `XplatEditorSurfaceProbe` serialized with `init`, `undo`, `exerciseTreeAPIAndReturnError:` only. Its `view` property (`UIView *`) and `snapshotAndReturnError:` (`NSString *` result) dropped silently because their types live in the dead modules — no error names the dropped members.

### Root cause

First error in `metadata-generation-stderr-arm64.txt`:

```text
iPhoneSimulator27.0.sdk/usr/include/DarwinFoundation1.modulemap:306:8: error:
  module '_c_standard_library_obsolete' requires feature
  'found_incompatible_headers__check_search_paths'
```

`DarwinFoundation1.modulemap` in iPhoneSimulator27.0.sdk declares `module _c_standard_library_obsolete` with `requires found_incompatible_headers__check_search_paths` — a clang feature newer than the generator's bundled clang 17. `_DarwinFoundation1` fails to build; `CoreFoundation` then fails, then `Foundation`, then `UIKit`, `WebKit`, and every dependent module — 240 `could not build module` errors cascade from the single unsatisfiable `requires`. The 8 surviving modules are those with no `_DarwinFoundation1` dependency. This is not flag-dependent: `requires` entries are evaluated against the compiler's feature set, not search paths.

### Contrast with prior evidence

The retained `apps/mobile` build products (2026-09-30, same `@nativescript/ios` 9.1.0 generator, then-installed iPhoneSimulator26.5.sdk) show 68,216 `verbose: Included` serializations including `NSObject`, `UIView`, `UITextView`, `WKWebView`, `UITextRange`, `NSTextStorage`, `NSLayoutManager`, `NSTextContainer`, `WKNavigationDelegate`, `WKUIDelegate`, and only benign exceptions (va_list `NSLogv`, unions, simd/Accelerate builtins). The metadata bin also contains exact strings for those symbols. Under the previous SDK the loss did not occur; under SDK 27.0 it does. The regression is the new SDK modulemap vs. the bundled clang 17, not the generator invocation — the umbrella in both runs enumerates UIKit/Foundation/WebKit headers.

### Verdict on the decision record

The supplied plan's metadata blocker is confirmed and now precisely characterized: under the current toolchain (Xcode 27.0 → iPhoneSimulator27.0.sdk, `@nativescript/ios` 9.1.0 clang-17 generator), **every NativeScript-hosted surface is blocked** — no `UIView`/`NSObject` metadata exists to subclass or instantiate, matching decision #101's stated stop condition. This blocks the adapter spike's NS-runtime gate (step 1) regardless of the clean compile/link result. The standalone native compile is unaffected; a non-NS host, an upstream generator update to a clang that recognizes `found_incompatible_headers__check_search_paths`, or a diagnosed modulemap workaround would each change this verdict and are out of scope here.
